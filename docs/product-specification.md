# Product specification

Respect tool permissions and stop only the affected action when genuine access, publishing, signing, or safety constraints prevent it.

PRODUCT AND BOUNDARIES

HypergateBar puts the current astrology in the macOS menu bar, with a full companion dashboard and configurable local reminders. Think CodexBar’s lightweight, open-source utility experience applied to astrology—not a fork of its provider-monitoring code.

This is independent of every commercial Hypergate product. Do not inspect, copy, modify, expose, or depend on private source, prompts, customer records, infrastructure, credentials, or operational records. No mandatory account, subscription, backend, paid API, AI model, analytics, or internet connection for core functionality. “AI” is the umbrella brand; astronomical events must be calculated, never generated by a language model.

Product name: HypergateBar.
Repository slug: hypergate-bar.
Intended GitHub owner: theleoking-astrology, identified through the connected GitHub profile during planning; verify locally before publishing.
Bundle identifier: ai.hypergate.HypergateBar.
Source license: MIT for our original code, preserving each dependency’s own license and notices. Keep trademark attribution separate; forks must not imply official endorsement, without adding restrictions to MIT-licensed code.
Initial platform: macOS 14+, Swift 6 language mode with a verified compatible installed toolchain. Apple Silicon is the first validated target. Build Intel/universal artifacts only when the toolchain supports them; distinguish cross-compilation from actual runtime testing.

ASTRONOMY ENGINE AND CONVENTIONS

Use the MIT-licensed C implementation of Astronomy Engine from cosinekitty/astronomy as the default offline provider. Inspect its actual C headers, implementation, tests, and license before wrapping it. Pin an immutable upstream revision. Vendor only needed source, data embedded in source, and required notices. Record revision, file hashes, provenance, and a reproducible verification/update script. Audit shared C state; serialize access through one shared executor when required, including access from separate provider instances.

V1 uses tropical, geocentric ecliptic longitude, with the ecliptic/equinox-of-date and corrections explicitly documented. Cover Sun, Moon, Mercury, Venus, Mars, Jupiter, Saturn, Uranus, Neptune, and Pluto. Do not substitute constellation boundaries, heliocentric longitude, or an unconverted J2000 coordinate for tropical longitude. Inspect API semantics carefully: a function containing “EclipticLongitude” in its name is not automatically geocentric.

Use a consistent, documented light-time/aberration/nutation policy. Handle UTC input and the provider’s UT/TT conversion correctly without applying delta-T twice. Persist event instants in UTC; use IANA time zones only for presentation and civil-time preferences. No birth information or location permission is needed for this geocentric feature set.

Document and enforce the supported date range after validation. Never invent live values. Fail explicitly on unsupported dates, invalid coordinates, or provider errors; show an unavailable/stale state rather than plausible fake data.

EVENT DETECTION

Calculate real events rather than inferring them from once-daily snapshots:

1. Moon and planetary ingresses: solve crossings of every 30-degree boundary. Detect both prograde entry and retrograde re-entry, including Pisces/Aries wraparound.
2. Hard aspects: squares at directed separations of 90/270 degrees and oppositions at 180 degrees. Deduplicate unordered body pairs without losing separate exact passes. Conjunctions and the minor hard aspects 45/135 degrees are separately configurable and OFF by default. Do not describe every conjunction as harmful.
3. Stations: solve for zero geocentric longitudinal velocity and verify the sign change on both sides. Positive-to-negative is station retrograde; negative-to-positive is station direct. Do not produce Sun/Moon retrogrades. A configurable “stationary” display threshold is not the exact station definition.
4. Current aspect status: show configured orb and applying/separating status derived from the changing angular error. An event occurring within an orb is not the same as its exact root.

Use angle unwrapping, adaptive search, and bracketed root refinement. Detect relative-motion turning points and subdivide searches so two crossings inside an interval are not missed merely because endpoint signs agree. Handle near-tangencies, repeated retrograde passes, roots at query boundaries, and half-open time windows. Verify the state immediately before/after an ingress. Use documented numerical precision; never equate a one-second root-solver tolerance with one-second astronomical accuracy.

Generate Today first, then progressively extend a cancellable cached forecast to 90 days. Reuse samples and invalidate caches by provider version and calculation settings. Bound query ranges and work budgets. “No matching event within this calculated window” must not become “this planet never retrogrades.” Keep event identities stable across recalculation and overlapping searches, while preserving genuinely separate passes. Match persisted events within a justified numerical tolerance instead of hashing unstable floating-point timestamps alone.

MENU BAR AND DASHBOARD

Use MenuBarExtra with a compact window-style popover and a deliberate menu-bar-first lifecycle. Provide an on-demand singleton Dashboard, native Settings, and a small first-run introduction. Closing the Dashboard must leave the menu-bar app running; Quit must actually quit. Do not steal focus during refresh. Provide keyboard access and a clear recovery path if the menu-bar item is removed.

The menu-bar label defaults to Moon symbol, current Moon sign, and an optional short next-ingress countdown. Offer icon-only and compact modes so the label remains usable on notched/small displays. Avoid long labels or a scrolling ticker.

The popover includes current Moon sign/degree and phase, next Moon ingress, next selected event, current retrograde planets, a few upcoming events, and Dashboard/Settings/Pause Alerts/Quit actions. All values come from the engine.

Dashboard sections: Today, Upcoming, and Planets. Show exact calculated local times, time-zone identifier, event filters, current planetary longitude and motion, next relevant events, and event details with UTC available. Display the calculation timestamp and forecast coverage. Handle degree/minute rounding at sign boundaries without incorrectly changing the sign.

Use premium native desktop design: strong typography, restrained ultraviolet accents, excellent dark/light appearances, native materials, accessible contrast, and no glitter, cartoon space backgrounds, oversized cards, or fabricated chart wheels. Respect reduced motion/transparency. Every glyph needs an accessible name; do not convey event meaning through color alone. Capture screenshots of the actual running application, not mockups presented as evidence.

REMINDERS AND USER CONTROL

Implement local notifications through UNUserNotificationCenter. Request permission only when the user explicitly enables alerts. Include permission status, a clearly labeled test notification, and actionable denied-permission guidance. The app remains useful when notifications are disabled.

Support per-event-type and per-body selection, exact-event alerts, selectable lead times, quiet hours, sound preference, pause/resume, and notification-click navigation to event details.

Initial defaults: Moon/planet ingresses and retrograde/direct stations enabled after consent; square/opposition alerts for non-Moon bodies enabled; lunar aspect alerts OFF to avoid notification overload. Suggested lead defaults are 30 minutes for Moon ingresses, 24 hours for other ingresses, 60 minutes for hard aspects, and 24/72 hours before stations, all editable. Leads and exact alerts must not duplicate one another when they resolve to the same delivery instant.

Separate pure notification planning from the macOS delivery adapter. Persist deterministic request IDs and reconcile the desired plan against actual pending requests. Use a bounded rolling queue; begin with a product budget of 48 total owned pending requests, reserve headroom for test/snooze operations, and verify actual behavior on supported macOS versions. Do not claim an iOS queue limit is a macOS guarantee. Show the last event actually covered by the queued reminders, which may be much sooner than the 90-day forecast.

Serialize reconciliation and guard against stale generations after awaits. Cancel/replace only HypergateBar-owned requests. Handle settings changes, launch, wake, clock changes, time-zone changes, denied/revoked permissions, scheduling errors, and restarts. Preserve physical UTC event instants across display-zone changes. Define quiet hours in the device’s current local civil time; suppress those deliveries by default and keep events visible in-app rather than delivering misleading late “exact” alerts.

Already scheduled notifications are system-managed, but indefinite replenishment requires the app to run again. Never promise exact delivery while the computer is asleep/off, during Focus, or without permission. After a long sleep, show missed events in-app instead of flooding the user with stale banners. Offer optional launch at login through SMAppService.mainApp, with an explicit user toggle and real registration-status/error handling. No hidden daemon, admin privileges, or persistent helper without a demonstrated need.

TESTS, ACCURACY, AND PERFORMANCE

Write failing tests before implementation and work in verifiable increments. Include:

- Angular normalization, wrapping, root boundaries, retrograde sign re-entry, repeated aspect passes, near-station searches, and station classification.
- Synthetic providers with known roots, derivative sign changes, tangencies, and two roots inside one initial interval.
- Independent reference fixtures for planetary positions and representative ingresses, aspects, and stations. Fetch reference data from JPL Horizons or another documented authoritative source using matched origin, frame, corrections, and time scales. Commit reproducible request metadata, provenance, and allowed fixture data so routine tests run offline. Our own provider’s output is not independent ground truth.
- A published accuracy matrix separating upstream angular accuracy, numerical convergence, and measured event-time differences by phenomenon. Set defensible criteria before accepting results; never silently loosen tests to make them pass. Mark failed or unverified accuracy honestly and block release claims that depend on it.
- Notification permission denial/revocation, idempotent reconciliation, concurrent settings changes, bounded queues, partial scheduling failure, quiet hours across midnight, DST transitions, time-zone changes, sleep gaps, and restart persistence.
- App lifecycle, settings persistence, CLI validation/schema, provider failure states, and offline operation.

Use Swift Testing/XCTest as appropriate. Inject a deterministic clock; no real waiting in unit tests and no network in ordinary CI tests. Run actual macOS UI smoke tests and document any OS notification interactions that could only be manually verified.

Keep idle CPU near zero: no every-second ephemeris recomputation, no busy loops, and no perpetual animations. Refresh visible position data only as needed and around event boundaries; stop view-only timers when closed. Measure launch, forecast generation, memory, and idle behavior on the actual machine. Report measurements with hardware and conditions rather than inventing performance numbers. Use structured local OSLog diagnostics with no telemetry or secrets.
